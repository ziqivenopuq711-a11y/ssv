Smart Contract Architecture

The SSV Network protocol is implemented as a set of upgradeable smart contracts deployed on Ethereum Mainnet. The architecture follows a modular design pattern with a main proxy contract delegating to multiple facets that implement specific functionality. Understanding this architecture is crucial for identifying potential vulnerabilities in the protocol.

All contracts use the OpenZeppelin upgradeable proxy pattern, with access control managed via role-based permissions. The DAO contract holds governance power over fee parameters and authorized upgraders. Security researchers should pay careful attention to initialization functions, storage layouts, and cross-contract interactions.

Key Security Considerations

Cluster Balance Management

Clusters maintain a running balance of SSV tokens that is deducted as operator fees are charged per block. A cluster can be liquidated if its balance falls below the minimum required threshold. Researchers should investigate edge cases in balance calculation, especially around the liquidation boundary, fee changes mid-epoch, and the interaction between multiple validators in a single cluster.

Operator Fee Update Mechanism

Operators can update their fees, but the protocol enforces a time delay and a maximum fee increase percentage controlled by the DAO. Potential attack vectors include front-running fee announcements, bypassing the fee increase limit, and manipulating the fee change timestamp to extract additional value from cluster operators.

Validator Registration & Exit

The validator registration process requires splitting a validator's BLS key into shares and distributing them to chosen operators. The on-chain registration only records a commitment to the shares. Security issues may exist in the share validation logic, the bulk registration process, or the exit mechanism that could allow unauthorized validator exits or double-registration attacks.

  • Check for missing access controls on sensitive state-changing functions
  • Verify that cluster nonce increments correctly to prevent replay attacks
  • Look for reentrancy opportunities in the SSV token deposit and withdrawal flows
  • Audit the liquidation reward calculation for manipulation vectors
  • Review the DAO fee update functions for governance attack scenarios

Previous Audits & Known Issues

The SSV Network smart contracts have been audited by leading security firms. Researchers should review prior audit reports to understand previously identified and resolved issues and focus on finding new vulnerabilities.
