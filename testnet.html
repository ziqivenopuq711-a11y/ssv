Testnet Scope & Environment

SSV Network Testnet deployments available for proof-of-concept development and vulnerability validation. Testnet findings may qualify for partial rewards.

Testnet Overview

The SSV Network Testnet is deployed on the Holesky Ethereum testnet and serves as the primary environment for protocol development, operator testing, and bug validation. Researchers are strongly encouraged to use the testnet environment to develop and validate their proof-of-concept exploits before reporting vulnerabilities through Immunefi.

While testnet contracts do not hold real user funds, vulnerabilities demonstrated on testnet that are reproducible on mainnet with the same code are considered valid bug bounty submissions. The testnet environment mirrors the mainnet deployment in terms of contract logic and architecture.

Important: Testnet mock contracts and test-only files are explicitly out of scope for rewards. Only bugs in testnet contracts that are identical to or closely mirrored by mainnet contracts are eligible.

Using the Testnet for Research

Setting Up Your Environment

To conduct research on the SSV testnet, you will need a Holesky-compatible Ethereum wallet with testnet ETH and SSV tokens, Foundry or Hardhat for contract interaction and exploit scripting, and access to a Holesky RPC endpoint such as those provided by Alchemy or Infura.

Writing Proof-of-Concept Exploits

All bug reports submitted to the SSV Bug Bounty Program should include a working proof-of-concept. The PoC should clearly demonstrate the vulnerability, the exact steps to reproduce it, and the impact. Testnet PoCs using Foundry's forge test framework are strongly preferred.

  • Use Foundry's forge script or forge test for reproducible exploits
  • Include all contract addresses, function selectors, and calldata used
  • Provide expected vs actual behavior with clear impact description
  • If applicable, include the Holesky transaction hash demonstrating the exploit
  • Document any prerequisites or specific blockchain state required to reproduce the issue

Testnet Scope Exclusions

The following are explicitly excluded from testnet scope and will not receive rewards even if a valid vulnerability is demonstrated:

  • Mock contracts and test helpers used only in unit tests
  • Contracts deployed solely for internal QA purposes
  • Vulnerabilities that require compromised validator keys or insider access
  • Issues in third-party dependencies not controlled by SSV Labs
